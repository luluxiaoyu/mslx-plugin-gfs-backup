# MSLX GFS 分级备份插件

MSLX GFS 分级备份插件用于解决服务器定时备份频繁、占用磁盘过大且无法长久留存历史存档的问题。插件在每次定时备份完成时，自动按周期提取「日备份、周备份、月备份」长线历史存档，并支持硬链接技术实现 0 额外磁盘空间占用。

---

## 工作原理

1. **事件触发**：监听 MSLX 宿主的定时备份完成事件。
2. **周期提取**：
   - **日备份**：每天首次备份时自动提取。
   - **周备份**：每周首次备份时自动提取。
   - **月备份**：每月首次备份时自动提取。
3. **滚动清理**：各周期备份独立维护最大保留份数，超出后自动滚动删除最旧的历史文件。
4. **硬链接存储**：默认使用硬链接模式，复用磁盘底层数据块，即使常规定时备份滚动删除，提取的归档依然完好无损且不占用额外空间（跨盘或网络存储可切换为独立副本模式）。

---

## 使用方法

### 1. 配置前置定时任务
插件依赖基础备份文件，请先在实例的 **「定时任务」** 中添加常规「备份存档 (Backup)」任务（建议每 2~4 小时执行一次）。

### 2. 配置分级备份策略
进入实例配置弹窗，切换至 **「分级备份设置」** 页面：
1. 打开 **分级备份功能** 开关。
2. 选择 **备份存储模式**（默认推荐「硬链接」）。
3. 选择 **提取时机偏好**（提取当期首个备份或覆盖保留最新备份）。
4. 设置各周期的 **最大保留份数**（例如：日备份保留 7 份、周备份保留 4 份、月备份保留 12 份）。
5. 点击 **保存备份配置**。

### 3. 查看与管理备份文件
在下方的 **「历史备份管理」** 中：
- 可通过选项卡快速切换查看「全部备份」、「日备份」、「周备份」、「月备份」。
- 支持按文件名与周期标记（如 `2026-09-17`、`2026-W38`、`2026-09`）进行搜索。
- 支持手动执行「清理过期备份」或单文件删除。

## 存储结构

归档文件保存在实例备份目录下的 `gfs-archives` 文件夹中：
```text
<实例备份目录>/
  ├── <常规定时备份文件>.zip
  └── gfs-archives/
      ├── daily/     # 日备份存档
      ├── weekly/    # 周备份存档
      └── monthly/   # 月备份存档
```

## 构建方式

```bash
# 1. 编译前端
cd Frontend
pnpm install
pnpm run build

# 2. 编译后端并打包 Release DLL
cd ..
dotnet build -c Release
```

编译产物位于 `bin/Release/net10.0/MSLX.Plugin.Gfs.Backup.dll`，将其放入 `DaemonData/Plugins/` 目录即可。
